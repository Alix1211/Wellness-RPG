## 확정한 게임 규칙
- 세로 화면 412×850, 320×640. 센터/회사/거리 의상, 3단계 난이도, 한 판 5회.
- 여성이 컨베이어로 오른쪽에서 왼쪽으로 접근합니다. 터치 순간 위치로 판정하며 75ms 스윙 준비 중에는 대상을 고정합니다.
- 타점 원/가까워질 때 색상 힌트는 제거했습니다. 너무 쉬워진다는 사용자 피드백입니다.
- 정확도는 시간 오차와 높이 오차 중 큰 값을 사용합니다. `precision = clamp(1 - max(dt/(window*2.2), dy/64),0,1)`.
- 비거리/점수: 헛스윙 0, 적중 `round(12 + 108 * precision^0.8)`. 같은 정타도 101m, 105m, 120m처럼 달라집니다. 랜덤 점수는 없습니다.
- 합산 최대 600m; `score`는 거리 합계, `ratio=score/600`. 기본 성공 기준 쉬움240/보통360/어려움456. `goal`로 변경 가능합니다.
- 정타1.25초/보통0.85초/빗맞음0.6초 비행, 판 사이0.4초. 예전 2.9초 비행으로 되돌리지 마세요.
- 여성 표시 크기는 220, 남성은 470×355의 0.95배. 여성 시트를 전체 연결 요소로 추출해 머리 잘림을 고쳤습니다.

## 소리 — 실기기 확인 필요
- 사용자 요청으로 단독 실행에는 소리가 있습니다. 공통 지시서의 초기 무음 규칙보다 이후 사용자의 명시적 요청이 우선합니다.
- 타격음은 Web Audio 합성 버퍼: 보통 팍/정타 퍽. 샘플0부터 시작, 중음과 잡음 스냅을 강화했습니다. 게임 시작 터치에서 AudioContext와 버퍼를 준비합니다.
- 타격음 gain0.95/master0.65. 일반 목소리는 75ms 뒤 gain0.60으로 시작해 타격음에 묻히지 않게 했습니다.
- 정타 목소리 `homerun`: 사용자가 제공한 홈런..mp3 (이야!!!). 정타는 gain1.15로 시작해 0.18초 유지 후 1.2초 동안 지수적으로0.10까지 줄이고 1.48초에0으로 마무리합니다.
- 보통 `normal`, 헛스윙 `miss`는 기존 제공 음성입니다. `perfect` 옛 기쁜반응은 데이터에 남아 있지만 현재 정타에는 쓰지 않습니다.
- 사용자 기기에서 타격음이 안 들린다는 피드백이 있었습니다. 중음/음량 보강 후 브라우저에서 버퍼 시작과 신호만 검사했습니다. 실기기에서 해결됐다고 확정하면 안 됩니다. 이 부분이 Claude 우선 점검 사항입니다.
- 예전 타격 파일에는 앞 무음0.59/0.73초가 있었습니다. 현재 합성 타격음에는 해당 무음이 없습니다. 음성도 디코딩 시 앞 무음을 건너뜁니다.

## 본체 연동
- `window.GAME_CONFIG`: roomId, kind=batting, location=center/company/street, difficulty=1/2/3, goal=null, images=[], lines={}.
- images[0]배경,[1]대기 여성 전체 프레임,[2]여성 비행,[3..]남성 스윙 프레임. sounds로 data URI 교체 가능(단 합성 hit_slap/hit_punch 키는 현재 makeHit 경로가 우선).
- iframe에서는 wellness-ready를 한 번 보내고 wellness-start를 기다립니다. 결과 wellness-result 한 번 후 정지, 재시작은 다시 wellness-start.
- 결과에는 score,ratio,success,detail,rounds[grade,score,distance,accuracy]가 들어갑니다. 부모만 저장/보상/방 이동을 처리합니다.
- wellness-pause/resume 지원. iframe에서는 로컬 시작/결과/설정 버튼을 숨기며 로컬 소리를 재생하지 않고 wellness-sfx만 보냅니다. 따라서 통합 후 타격/음성/페이드는 호스트가 따로 연결해야 합니다.
- 현재 sfx 이름 swing,hit_perfect,hit_good,hit_bad,miss,success. 미리듣기 같은 음향 설명창을 게임 화면에 새로 붙이지 마세요.
