# GAIA Pingpong Champion — 적 전용 변칙 기술 Work 인수인계

작성일: 2026-10-24  
상태: **구현 의뢰서 / 아직 구현되지 않은 새 방향**

## 0. 가장 중요한 결정

현재 시험판은 **미주(플레이어)가 변칙 기술을 선택하여 사용하는 구조**다. 이번 작업의 목적은 이를 **상대 선수(AI)가 미주에게 패널티를 거는 구조**로 바꾸는 것이다.

- 사용자가 직접 플레이해 보니 기존 AI 상대들이 너무 약했다.
- 기술을 미주가 AI에게 쓰면 실질적으로 효과가 없거나 체감이 약하므로, **상대 선수에게 반칙성 패널티 기술을 장착**한다.
- 장르 감각: 정통 시뮬레이션보다는 **마리오 테니스/마리오 카트처럼 웃긴 변칙 경기**. 다만 기존 탁구 물리·카드·월드투어·아케이드 구조는 유지한다.
- 세계관: **26명의 상대 탁구 선수는 모두 성인 여성이고 마조히스트**다. 남성 신사나 남성 선수를 만들어 넣지 않는다. 선수마다 수줍음/도발/자존심 등의 성격 차이는 가능하다.
- 기존 게임을 새로 만들거나 메인 UI를 재설계하지 말 것.

## 2. 새 전투 규칙

1. **각 상대 선수에게 고유 기술 한 종류를 배정**한다. 선수 26명에 8종 기술을 재사용해도 된다. 별도의 복잡한 해금/장착 UI는 만들지 않는다.
2. 상대 AI가 **한 경기당 최대 1회** 자기 기술을 발동한다. 1포인트마다 재사용하지 않는다.
3. 상대가 기술을 쓰는 순간 **해당 여성 선수의 기존 초상화가 0.4~0.6초 정도 짧게 등장**하고 저질스럽지만 코믹한 기술명이 함께 나타난다. **경기를 멈추지 않으며**, 공·라켓·점수·조작을 가리지 않게 화면 가장자리에 배치한다.
4. 미주에게 불리한 효과 또는 상대에게만 유리한 효과로 구성한다. **상대 AI의 시야/판정을 떨어뜨리는 기존 효과는 제거**한다.
5. 랠리 종료, 경기 종료, 다시 시작, 다른 상대와의 새 경기에서 기술 효과와 사용 기록이 올바르게 정리되어야 한다. 새 경기에서 1회 사용 가능 상태로 초기화한다.
6. 약한 동네 상대의 긴장감부터 높이는 게 목적이다. 기술 효과는 피하거나 극복할 여지가 있어야 하며 일방적으로 자동 실점시키지 않는다. 리그별 강도 증가는 테스트 후 조절한다.

## 3. 기술 매핑 — 피해 대상 주의

| 번호 | 기술(임시 이름) | 대상/구현 의도 | 기존 실험과의 차이 |
|---|---|---|---|
| 1 | 왕방울 서브 | 공 거대화. **미주의 리턴에 불리한 궤적/바운드**를 시험 | 단순히 커져서 더 쉬워지지 않도록 물리 효과 점검 |
| 2 | 콩알 서브 | 공 축소로 미주가 보기/맞히기 어려움 | AI 판단을 약화시키지 않음 |
| 3 | 10초 폭탄공 | 미주를 압박하는 카운트다운 공 | 원 실험의 10초 규칙은 보존한 채 실제 짧은 랠리에서 작동성 점검; 변경 전 보고 |
| 4 | 제 것 좀 보세요! | **상대 여성 선수의 라켓만 확대** | 기존의 '내 라켓 확대'를 상대 쪽으로 반전 |
| 5 | 쪼그라들어라♡ | **미주의 라켓만 축소** | 기존의 '상대 라켓 축소'를 미주 쪽으로 반전 |
| 6 | 미끈미끈 서비스 | **미주의 이동에만 미끄러짐/관성** | 기존 AI 미끄러짐을 미주 입력 쪽으로 변경 |
| 7 | 수상한 액체 발사! | **미주의 실제 게임 시야**에 분홍 물감/얼룩 잠깐 표시 | 상대 코트에만 표시하거나 AI 지연을 주지 않음 |
| 8 | 핑크 안개 작전 | **미주가 바라보는 경기 화면 일부**를 핑크 안개로 가림 | 기존 AI 시야 패널티 제거 |

참고: **라켓 크기 규칙은 사용자 확정**이다. 축소는 반드시 미주 라켓만, 확대는 반드시 적 라켓만 적용한다. 나머지 효과의 정확한 수치/지속시간은 기존 시범 값을 출발점으로 하되 실제 조작감을 보고 조정한다.

## 4. 초상화 컷인과 대사

- 별도의 인물 재생성 금지. **기존 26명 상대 여성 초상화 에셋 재사용**. 실제 파일 경로와 선수 ID 연결은 소스에서 확인한다.
- 같은 8종 기술이라도 선수별 대사는 나중에 달리할 수 있다. **우선 기술 8종 각각에 한 줄**만 정해 작은 범위로 구현한다.
- 임시 대사 예시: `어머, 작아졌네?`, `미끈미끈 서비스♡`, `제 것 좀 보세요!`, `받아주세요♡`.
- 0.4~0.6초 짧은 컷인, 밝고 귀여운 핑크/민트 분위기. 긴 컷신, 게임 일시정지, 새 설정 버튼 추가 금지.
- 플레이 중 점수/HP/공/버튼이 가려지지 않는지 **가로·세로 양쪽**에서 확인한다.

## 5. 현재 시험판과 혼동하면 안 되는 것

- 옛 시험: **미주가 직접** 8개 중 하나 골라 경기당 1회 발동. 화면 우하단 `🎲 변칙 기술` 메뉴.
- 새 방향: **상대 AI가 자기 기술을 자동으로** 경기당 1회 사용. 미주용 메뉴는 경기 화면에서 제거하거나 숨기되, 필요하면 개발용 테스트 진입 수단만 별도 유지.
- 이전에 논의했던 '승리한 선수의 기술을 미주가 자동 획득'은 **이번 범위에서 보류**. 지금은 약한 AI를 패널티 기술로 강화하는 데 집중한다.
- 기존 물리·AI 실력 수치 자체를 무단으로 크게 변경하지 않는다.
- 게임의 패널티 미니게임, 맵, 카드 이동, 골드, 기존 승패/성장 규칙은 수정 대상이 아니다.

## 6. 필수 검증과 전달 방식

1. 각각 8종의 기술이 **미주 쪽에만 불이익**을 주거나 적에게만 이익을 주는지 확인한다.
2. **상대 기술 경기당 1회**, 라운드 초기화·새 경기·재도전·월드투어/아케이드 진입 상태 점검.
3. 라켓 축소/확대는 **겉모양뿐 아니라 실제 타격 판정**까지 일치해야 한다.
4. 초상화가 **해당 상대 선수**인지, 컷인 이후 터치/경기 루프가 정상인지 점검.
5. 가로·세로에서 점수/조작부/공을 가리지 않는지 점검. 검증하지 못한 항목은 미검증이라고 정확히 보고.
6. 기존 시험판은 HTML만 전달할 때 **이미지가 깨졌음**. v12.11은 `assets/main`, `assets/minigames` 등 **총 522개 이미지·폰트 자산을 외부 경로로 참조**한다. 새 HTML과 원본 `assets/` 폴더의 상대 경로를 유지해야 한다. HTML 단독 패키지를 '완성본'이라고 부르지 않는다.
7. **GitHub는 안정 버전과 분리된 작업 브랜치**, 변경 기록 MD 작성. 사용자에게 줄 때는 전체 게임 55MB를 반복 배포하지 말고 **수정 패치 ZIP 우선**. 단, 태블릿에서 처음 실행할 수 있는 전체 패키지를 요청받으면 `assets`까지 포함해 CRC/경로 검증 후 별도로 제공한다.
8. 구현 뒤 실제 동작 상태(완료/미구현/미검증), 브랜치/커밋, 수정 파일 목록, 실행법만 짧게 보고한다.
