# 스킬 컷인 후 터치 잠김 수정

2026-10-24. 앞선 큰 초상화·말풍선 컷인 패치의 입력 버그만 수정했습니다.

## 원인

컷인 중 전역 입력 차단기가 touchend를 막으면서 isTouching만 false로 바꾸고 activeRacketTouchId는 남겼습니다. 이후 새 touchstart는 기존 ID가 있다는 이유로 거부됐습니다.

또한 컷인 화면 위에서 시작한 터치는 컷인이 사라져도 DOM 이벤트 대상이 원래 컷인 요소로 남습니다. ID만 복원해도 canvas의 touchmove 핸들러에 도착하지 않아 조작이 이어지지 않았습니다.

## 수정

- 컷인 중 손을 떼거나 취소하면 이전 터치 ID와 속도를 정리합니다.
- 컷인 중 현재 눌린 손가락 ID와 최신 좌표를 추적합니다. 이 동안 라켓·카메라·공의 정지는 유지합니다.
- 재개 시 현재 누르고 있는 손가락을 복원하고, 조작 목표를 최신 위치로 연결합니다.
- 컷인 위에서 시작한 터치는 그 제스처가 끝날 때까지 이동·종료를 이어서 처리합니다.
- 재개할 때 라켓을 강제 순간이동시키거나 쌓인 입력으로 스매시를 만들지 않도록 속도·동작 기록을 정리합니다.
- 일반 canvas 입력은 원래 핸들러를 유지합니다.

수비 AI, 공격 패턴, 지정 스킬, 효과 강도·지속시간, 점수, 이미지, 골드·경험치·저장 규칙은 변경하지 않았습니다.

## 검증

PC Chromium의 모바일 터치 에뮬레이션에서 CDP로 실제 touchStart/touchMove/touchEnd 이벤트를 전달했습니다.

- 이전판: 컷인 중 손 떼기 → 다시 누르고 유지 → 재개 후 이동 입력이 무시되는 버그를 재현했습니다.
- 수정판 가로 956×493: 이전 ID 해제, 컷인 중 다시 누른 손가락으로 재개 후 이동, 라켓 실제 이동을 확인했습니다.
- 수정판 세로 495×909: 같은 경로와 라켓 실제 이동을 확인했습니다.
- 두 화면에서 재개 후 새로 누른 첫 터치도 바로 등록·이동함을 확인했습니다.
- 검사 중 JS pageerror 없음. 최종 HTML 구문 및 수비 AI 동일성 검사 통과.

실제 Android 기기 테스트는 아닙니다. 전체 15종 효과와 다른 미니게임을 다시 반복 검사한 것은 아닙니다.
