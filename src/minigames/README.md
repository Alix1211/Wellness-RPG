## 방 매칭 제안 (이전 기록)

아래 표는 초기 제안이며 이후 사용자 결정으로 대체되었다. 실제 센터 배치는 ../center/model.js와 ../center/README.md가 기준이다. 소시지는 개인사무실/침실, 뒤를 조심은 체벌방으로 확정되었다. 기구방은 줄 자르기, 화장실은 물병 채우기를 새로 만들 계획이다.

| 방 | 미니게임 | 플레이 |
|---|---|---|
| 기초방 | 물어와! | 전진 연타와 점프로 장애물을 넘어 물건 회수 |
| 기구방 | 소시지 합치기 | 같은 단계끼리 합치는 물리 퍼즐 |
| 단체방 | 움찔 찾기 | 9칸 중 움직이는 대상을 찾아 누르기 |
| 자세 점검방 | 아슬아슬 균형 잡기 | 좌우 조작으로 컵 균형 유지, 세 번 떨어지면 종료 |
| 체벌방 | 백만 대 챌린지 | 세 대상의 게이지를 번갈아 눌러 유지하기 |
| 단체방 (추가 후보) | 뒤를 조심!! | 당겼다 놓는 발사로 움직이는 대상 맞히기 |

원본은 방마다 게임이 고정되어 있지 않고 랜덤 이벤트로 여섯 종류 중 하나를 고르는 구조다. 위 표와 room-matching.proposal.json은 대화를 위한 제안이며 실제 방에 적용하지 않았다. 원본 special(별도 훈련방)은 사용자가 화장실 훈련방으로 확정했다. 화장실용 게임은 미배정으로 두고 별도로 논의한다. 뒤를 조심!!은 단체방의 추가 게임 후보로 옮겼다. 특수훈련실(elite)은 새 게임 없이 기존 게임의 상위 난도 재사용 후보로 남겨 둔다.

로비는 접수·대기, 회복방은 자원 회복, 매점은 아이템 구매 역할로 우선 둔다. 회사·집의 재사용 미션, 방마다 어떤 스탯이 얼마나 오르는지, 스킬, 체력과 M파워 소모는 아직 확정하지 않았다.

## 가져오기와 실행 연결은 다름

현재는 원본 코드와 리소스를 보존한 가져오기 단계다. 여섯 게임 전체가 RPG에서 실행되도록 연결된 상태가 아니다. minigames.js는 원본의 S/ROOMS/저장/렌더/행사 루프 및 footer에 의존한다. 따라서 원본 파일을 RPG에 script로 바로 추가하지 않는다. 다음 구현 때 호스트 어댑터로 시작·종료·결과만 연결하고 원본의 자동 성장/저장/방 행사 루프는 활성화하지 않는다. 물어와는 FetchGame 클래스가 분리되어 있다.

RPG 확정 스탯은 색기(ki), 음란도(um), 복종도(bo), 개방성(ge) 4종이며 자원은 HP와 M파워(마조력)다. 플레이 성적에 따른 성장만 구현하고 방에 가만히 있는 자동 성장은 도입하지 않는다. 기존 소시지+영상 단독 테스트는 tests/sausage-video-test.html에 유지된다.

## 출처와 검증

import-manifest.json에 각 파일의 원본 Git blob SHA·크기·경로를 남긴다. 복사본 전체를 Git blob SHA로 대조하고 세 JavaScript 파일의 문법을 검사한다. 이는 원본 보존 및 문법 검사이며 RPG 실행 통합 검증은 아니다.
